### Blocked / not implemented: Decision 12 (L6982)

Did not implement "release the `OpenWorkState` guard before the core call" for the async
wrappers in `commands/glossary.rs`. Found a real technical wall partway through, not a scope
judgment call I felt safe making unilaterally:

- `Store` deliberately does **not** implement `Clone` (its `Drop` runs `close()`/TRUNCATE; a
  clone would make "who closes" ambiguous). `OpenWork` owns a `Store`, not an `Arc<Store>`.
- Every async wrapper's "core call" (e.g. `resolve_term_for_quick_add`, `add_manual_term`)
  needs a live `&Store` for its entire duration. You cannot drop the `MutexGuard<Option<
  OpenWork>>` and keep passing a reference derived from it — the borrow checker won't allow it,
  and there's no cheap owned handle to extract instead.
- The one place in the codebase that genuinely does "enqueue while locked, release, wait
  unlocked" (`spawn_import_scan`'s `filter_and_enqueue_current_import_scan` /
  `ticket.wait()`) works because `Store::enqueue` returns an owned `WriteTicket<T>` (an
  `mpsc::Receiver`, not a borrow) — but that ticket-based API only exists for **writes**, and
  restructuring `add_manual_term`/`update_manual_term`/`resolve_term_for_quick_add`/etc. to
  return tickets instead of blocking would change their public (pure-layer, test-facing)
  signatures — a materially bigger change than "release the guard," touching every existing
  test that calls them directly.

Two ways forward, un-picked (per root `AGENTS.md`: two valid options ⇒ present both to Ice,
don't just choose):

- **(A) Narrower goal:** only restructure the wrappers whose core call is itself a single
  `Store::write` (not a read+decide+write) to use the ticket pattern; leave read-shaped
  wrappers (`glossary_lookup_term`, `list_all_entries`-backed `glossary_list_entries`) alone,
  since `ReaderPool` contention was never measured as a real problem (only `Store::write`'s
  serialized single-writer-thread cost was the original NFR2 worry).
- **(B) Wider goal (what Decision 12's wording literally asks for):** needs `OpenWorkState` to
  hold something cheaply shareable (e.g. `Arc<Store>` instead of `Store`) so a wrapper can grab
  a clone and drop the outer lock immediately — this is an architectural change to `OpenWork`/
  `Store` ownership, not a "narrow the lock scope" edit, and per root `AGENTS.md` belongs to
  Winston as a new AD, not to a story's Rust phase.

The spec's acceptance criterion for this ("a second Glossary command locks `OpenWorkState`,
then it is not blocked for the length of that core call") is **not met**. `deferred-work.md`'s
L6982 line should stay open, `Chủ:` reassigned per whichever option Ice/Winston pick — I did
not touch `deferred-work.md` (that's Task 4, a later phase).
