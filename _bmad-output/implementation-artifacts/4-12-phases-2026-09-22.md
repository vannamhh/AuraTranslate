**The three questions this phase's own header asked to have answered:**

1. **Where the anti-persist guard sits, precisely enough to delete it in one edit.** Two
   places, not one — Phase 4's counter-check 3 targets the first:
   - `WorkspaceDock.vue::onLayoutChange()`, **first line**: `if (suppressPersist) return`.
     Deleting this one line is the counter-check: every `autoHide`/`autoShow`/merge mutation
     still brackets itself with `suppressPersist = true/false`, but with the guard gone that
     flag no longer stops `onLayoutChange` from marking the schedule dirty, so a plain resize
     that crosses a tier boundary will — after the guard is removed — eventually call
     `flush()` and `emit('persist', …)` on its own idle timer. That is the red the
     counter-check is written to produce.
   - `WorkspaceDock.vue::applyTier()`, **first line**: `flush()`. This is a *second*, additive
     piece I added beyond what this phase file anticipated, guarding a **different** leak (a
     write already dirtied by a real user action, still pending, gets contaminated by a
     subsequent automatic mutation before it fires) — removing only the `onLayoutChange` guard
     (not this line) still reproduces the counter-check's red, because the newly-unguarded
     auto-mutations start marking *new* dirt themselves once the primary guard is gone. I
     verified this reasoning rather than assuming it; see the spec note for the full argument.
     Phase 4 does not need to remove this second line for the counter-check to go red, but
     should know it exists so a future "the guard doesn't work" report checks the right line.
2. **Every `data-*` hook a test can select on.** Three, all on `.dock-host` (the
   `WorkspaceDock.vue` template root): `data-layout-tier` (`full`/`short`/`narrow`/
   `unsupported`, absent only for the single synchronous instant before `onReady`'s first
   `measureAndApplyTier()` resolves), `data-layout-preset` (the live `PresetId`), and
   `data-layout-merged` (`"true"` while the `short`-tier merge is active, attribute absent
   otherwise — an explicit string, not a bound boolean, so absence/presence is unambiguous).
   No geometry, no pixels — these expose computed STATE only, matching the spec's ban on

3. **Whether a manual `layout.toggle_*` hide and an automatic tier hide are distinguishable at
