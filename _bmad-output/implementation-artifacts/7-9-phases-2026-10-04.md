## Wire shapes (snake_case fields; arguments camelCase on invoke)

- `invoke('tm_list_pairs', { origin, tier, search })` (async) -> `{work_open, tm_empty, health: [{translation_origin: "self"|"other"|"bilingual_import", count}] (always these 3, in this order, over the tier filter only), total_pairs, total_groups, groups: [{source_text, distinct_targets, rows: [{tier: "work"|"global", unit_id, target_text, translation_origin, side: "mine"|"others", created_at}]}]}`. `groups.len() <= 200`; `total_groups` is the "N" of "200 / N". A group header is shown when `distinct_targets >= 2`; otherwise render the lone group as plain rows (a group may still hold several rows with one distinct target). `origin`: `all|mine|others|self|other|bilingual_import`; `tier`: `both|work|global`; anything else -> `tm.invalid_filter`. `search` blank = no search. `tm_empty` (both tiers hold nothing) differs from "filters hide everything". With no Work open the Work tier is simply absent (`work_open: false`).
- `invoke('tm_update_pair_target', { tier, unitId, targetText })` -> `{tier, unit_id, source_text, target_text, translation_origin, side, created_at}` (the pair as stored after the edit, origin `self`). Errors: `tm.target_empty` (blank after trim, nothing written), `tm.pair_not_found` (gone or bad tier), `work.none_open` (tier work with no Work).
- `invoke('tm_delete_pair', { tier, unitId })` -> `null`. Error: `tm.pair_not_found`. No second-press logic in Rust (two presses live in the webview).
- `invoke('tm_delete_others', { tier })` -> `{deleted_work, deleted_global}`. Deletes `other` and `bilingual_import` pairs in the tiers `tier` shows, ignoring origin filter and search. `tier = work` with no Work -> `work.none_open`; `both` with no Work = Global only. Confirm text count = sum of health `other` + `bilingual_import` over the same tier filter (the webview already holds it from the last list).
- `invoke('tm_push_pair_to_global', { unitId })` -> the new Global pair (same shape as update; new `unit_id`, same origin and `created_at`). Errors: `tm.pair_not_found`, `tm.global_pair_exists` (identical source+target already in Global, nothing written), `work.none_open`. All error `message_key` are `Unknown`; the webview maps by `code`.
- All write commands re-read by tier and id inside the write; the webview should re-list after any success.
