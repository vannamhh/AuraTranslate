## Wire shape (snake_case, no rename)

- `invoke('tm_fuzzy_matches', { segmentId })` -> `{segment_id, matches: [...unchanged, no created_at], exact: [{tier: "work"|"global", unit_id, target_text, side: "mine"|"others", created_at}]}`. `exact` is non-empty only with 2+ distinct targets, already in display order (newest first within side and tier), and then `matches` is `[]`. `created_at` is ISO-8601 UTC with ms (`2026-08-03T00:00:00.000Z`); render through `historyTimeLabel`. "In use" mark = the row whose `target_text` equals the current text (webview comparison).
- `invoke('tm_concordance', { query })` hits gain `created_at` (same format).
- `invoke('accept_tm_exact', { segmentId, tier, unitId, force })` -> same `PromoteAiTranslationOutcome` as `accept_tm_fuzzy` (`segment_id, target_text, translation_origin, status, needs_confirmation, unsigned_draft`). Writes the PAIR's own origin (`self`/`other`/`bilingual_import`), `draft`, baseline set, no SegmentVersion. `needs_confirmation: true` (nothing written) only when current text is non-empty, differs from `baseline_target_text` and has no copy in `segment_version`; webview re-calls with `force: true` after asking. Errors: `tm.pair_not_found` (pair gone, bad tier, or pair source no longer equals the segment source), `work.none_open`, `segment.not_found`, `segment.retired`.
