## Per question
1. Caching: all four vendors discount cached input to about 10% of input (DeepSeek about 1-2%, the deepest). Gemini implicit needs a 4,096-token prefix on 3.x Flash; OpenAI needs 1,024; Anthropic needs explicit cache_control with a 1.25x write cost; DeepSeek caches automatically. Layout everywhere: system prompt and glossary first, variable chapter text last. Unconfirmed: whether Gemini implicit caching triggers through the OpenAI-compat endpoint (only explicit `cached_content` via extra_body is documented).
2. Batch: 50% off at OpenAI, Gemini, Anthropic and Qwen (Qwen China only), with 24h targets. Gemini's compat layer cannot upload or download files, so it needs the native client. It does not suit a user waiting on a chapter, but it fits an "overnight whole-book" mode. Anthropic and OpenAI turnaround numbers were not fetched this round. Batch and cache discounts stack at Anthropic but not at Qwen.
3. Output format: no direct evidence found. Only indirect: JSON parse failures are <1% for strong LLMs. Needs a second round.
4. Thinking: billed as output. On Gemini 2.5, `reasoning_effort:"none"` disables it; on Gemini 3 and 2.5 Pro it cannot be turned off, only lowered to `minimal`/`low`. The one study found (snippet only) says reasoning hurts translation, so keep effort minimal.
5. Prices: see table. Cheapest capable tier on paper is Haiku 5.5 / DeepSeek flash / gpt-5-nano. Gemini Flash prices double on 2027-01-01.
6. Request batching: not directly sourced. Inference from the numbers: with a ~90% cached-input discount and a prefix above the threshold, repeating the system prompt and glossary per request costs about 10% of the uncached rate, which weakens the case for packing many segments per request. Per-request cache misses (Gemini 4,096 minimum, TTL expiry) reverse that. This is inference, unverified.
