## src-tauri/ — Rust + Tauri v2

The application core; every business rule lives here (AD-1). `rust-version 1.85`, deliberately different from `tools/dict-build` — don't sync them. Read `SECURITY-NOTES.md` before touching `tauri.conf.json` or `capabilities/`.

## Conventions

- 🔴 `panic = "abort"`: a panic kills the process — no unwind, no `Drop`, no WAL flush. No `unwrap()`/`expect()` under `core/store/**`; lock with `lock().unwrap_or_else(|e| e.into_inner())`; reply with `let _ = tx.send(…)`. A dependency's panic points are an architectural decision (why `docx_rs` was rejected). Test builds always `unwind`, so no green test proves `abort` behaviour.
- 🔴 Every IPC surface has two layers: ① a pure function taking `Option<&Store>` (what `tests/**` calls); ② a thin `#[tauri::command]` in a nested `wire` module that uses `try_state`, never `state()`.
- IPC errors only through `IpcError::new(code, message_key, params, retryable)`. No struct literal, no `rename_all` (field names are wire, locked by `tests/ipc_contract.rs`).
- `message_key` and scope kinds are closed catalogues generated by `message_keys!` (`core/i18n/`) and `scope_kinds!` (`core/scope/kinds.rs`). Never hand-write a parallel list.
- No display text in Rust, not even `impl Display` (diagnostics only, unaccented). String literals under `src/**` are unaccented; `tests/**` is exempt.
- Modules are named by domain concept; `C1`–`C10` never appear in a module name.
- Test files: `*_contract.rs` (wire shape, declared tables, registered keys) · `*_boundary.rs` (which module may not carry another's vocabulary). Test names are assertive sentences.
- Pin crates with `=`. `[profile.release]` is frozen. `[features]` has no `default`.

## Known pitfalls

- 🔴 `capabilities/` holds exactly one file, `main.json` — Tauri loads every file in it. Permissions are exactly `core:path:default` · `core:event:default` · `core:resources:default`; adding one is an architectural decision.
- The CSP is never loosened (no CDN, external fonts or images). `assetProtocol.scope` is `$RESOURCE/fonts/**` only.
- 🔴 No listening port in a release build (AD-45): server tooling needs `optional = true` + a non-default feature AND `#[cfg(debug_assertions)]` at the seam.
- AI streaming goes through the Tauri Channel API, with no auto-reconnecting SSE client (AD-22); every AI call is cancellable. API keys stay in Rust (`keyring`), never over IPC.
- Every write goes through its store's `store::Writer`. `PRAGMA wal_autocheckpoint = 0`. Migrations are forward-only, in a transaction, after a backup; a newer schema ⇒ refuse to open, never write.
- Editor flush (AD-35): idle 2 s · hard cap 5 s not reset by keystrokes · confirm · leaving a segment · closing a Work; done only once it reached the WAL. Discrete actions (FR94, FR58) write immediately.
- Never merge dictionary sources; `source` is mandatory on every sense record; don't merge `zh` with `en`. Nothing writes to the Glossary without the user's approval (pending table first).
- zh/en routing keys on the SHAPE of the query string, not the Work's language. Lower-casing adds a key, never replaces the original.
- No `LIKE` on the lookup hot path.
- SQLite `trim()` strips only ASCII space: DDL empty-guards list all 25 `White_Space` code points (`GLOSSARY_ENTRY_DDL`), the same set as Rust `str::trim()`; change both together.
- AD-13 is guarded by `tests/ai_boundary.rs`; AD-41 by `webimport_boundary.rs` and `webimport_contract.rs`.

### Import pipeline

- Step order is the value `PIPELINE_ORDER` in `core/segment/pipeline.rs`, validated once by `validate_order`. When adding a step, state what earlier steps already consumed: line-joining runs before Chapter splitting, and the `Blob`/`.docx` paths run steps 3–4 on one whole-document unit.
- Anything keyed on `segment.ord` (including `asset` rows) is maintained inside the four Chapter-reorganising transactions.

### Derived stores: `library-index.db` and `meta.json`

- Both are derived. Only `Indexer` writes `library-index.db`, after `.atproj`. Deleting `meta.json` is always safe. `open_work` only reads them.
- The orphan flag lives in `global.db` table `library_orphan`. 🔴 `Indexer::rebuild` writes `global.db` first, then deletes from the index.
- ⚠️ `global.db` migrations are one-way (AD-30): a downgraded build refuses to open it.
- `library_work` is rewritten in place on every bump; `status IS NULL` / `chapter_done_count IS NULL` mean not yet known.
- `rebuild` opens each `project.db` read-only; a missing, corrupt or newer one skips only its text (`RebuildOutcome::text_skipped`).
- ⚠️ A new write path into `segment` or `chapter` must run `Indexer::rebuild` afterwards; the four Chapter operations use the template in `commands/lifecycle.rs`. Nothing goes red otherwise.
- 🔴 `library_target_fts_nd` never runs alone (AD-27): the main index runs first; `_nd` only for `Lenient` or when the exact run returned 0 on a non-empty index. The source half has no `_nd` index.
- Reasoning: §Design Notes of stories 5-3, 5-4, 5-5, 5-8, 5-9, 5-10.
